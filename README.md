# 한끼노트 — SQLite 레시피 앱

## 실행

Node.js 24 LTS와 Express 패키지를 설치했습니다. Windows에서 프로젝트 폴더의 start.cmd를 더블 클릭하거나 터미널에서 .\start.cmd 를 실행합니다.

브라우저에서 http://localhost:3000 을 엽니다. 서버 터미널은 열어두고, 종료는 Ctrl+C입니다. 이제 Live Server가 아닌 이 주소에서 앱을 사용합니다.

일반 Node.js 24 환경에서는 npm install 후 npm start도 가능합니다. 이 컴퓨터에서는 .runtime/node-v24.22.1-win-x64/에 프로젝트 전용 Node.js를 설치했으므로 전역 PATH 수정이 필요 없습니다. SQLite 드라이버는 Node.js 내장 node:sqlite를 사용하며 Express는 npm으로 설치했습니다.

## 저장과 로그인

- data/hankki.sqlite에 계정, 레시피와 압축된 사진, 별점, 댓글, 북마크, 로그인 세션을 저장합니다. 첫 실행 시 자동 생성됩니다.
- 새로고침과 서버 재시작 후에도 데이터가 유지됩니다. 로그인은 HttpOnly 쿠키로 최대 7일 유지되며 로그아웃 시 서버 세션이 삭제됩니다.
- 비밀번호는 서버에서 임의 salt와 scrypt로 해시합니다. 비밀번호 해시와 세션 토큰은 화면 API로 반환하지 않습니다.
- 서버에서 작성자 권한을 검사합니다. 레시피는 본인만 수정·삭제하며 다른 계정의 평가·댓글을 변경할 수 없습니다.
- 별점과 댓글은 별도 테이블에 저장합니다. 각각 계정·레시피별 1개 제한을 DB 기본키로 보장하며 삭제는 서로 영향을 주지 않습니다.
- 북마크도 계정별로 저장하며 ‘저장 많은 순’은 DB에 저장된 모든 계정의 저장 횟수를 기준으로 합니다.
- ‘자주 찾는 메뉴’는 검색 버튼·Enter 또는 인기 검색어 버튼으로 실행한 검색을 SQLite에 집계하여 상위 3개까지 표시합니다. 입력 중에는 집계하지 않으며 빈 검색어도 제외합니다. 검색 기록이 없으면 표시하지 않습니다. 대소문자·중복 공백·전각 문자를 정규화해 같은 검색어로 집계하고, 횟수가 같으면 최근 검색 순으로 표시합니다.
- 사진은 최대 20MB까지 선택할 수 있고 긴 변 최대 1280px JPEG로 축소해 저장합니다. 브라우저가 지원하지 않는 HEIC는 JPG/PNG로 변환해주세요.

이제 브라우저 localStorage는 앱 데이터 저장에 사용하지 않습니다. 기존 데이터 내보내기 페이지에서만 이전 자료를 읽습니다.

data/에는 개인정보가 포함됩니다. Git에서 제외되며 웹 서버로 제공되지 않습니다. 백업은 서버를 종료한 뒤 data/ 폴더 전체를 복사하세요. 실행 중인 DB는 WAL 파일도 함께 관리되므로 .sqlite 파일만 복사하지 마세요.

서버는 현재 컴퓨터의 127.0.0.1에서만 실행합니다. 외부 사용자용 배포에는 HTTPS와 운영 환경 설정이 별도로 필요합니다.

## 기존 localStorage 데이터 가져오기

기존 브라우저 데이터는 삭제하지 않습니다. 포트가 바뀌면 브라우저 저장 영역도 달라지므로 다음 절차로 옮깁니다.

1. 기존에 사용하던 Live Server를 열고 같은 호스트와 포트에서 legacy-export.html을 엽니다. 예: http://127.0.0.1:5500/legacy-export.html
2. 기존 계정을 선택하고 백업 JSON을 내려받습니다. 계정 비밀번호는 포함되지 않습니다.
3. http://localhost:3000 에서 새로 회원가입·로그인합니다.
4. 화면 하단 ‘백업 가져오기’에서 JSON을 선택합니다.

선택한 기존 계정의 레시피·평가·댓글, 계정 없이 등록한 레시피와 연결된 북마크를 현재 로그인한 계정으로 가져옵니다. 다른 사람의 글과 평가는 가져오지 않습니다. 같은 백업을 다시 가져와도 레시피가 중복되지 않습니다. 서버에 이미 등록된 내 댓글과 평가는 덮어쓰지 않습니다.

## 테스트

프로젝트 폴더에서 다음 명령으로 실행합니다.

    .\.runtime\node-v24.22.1-win-x64\node.exe --test test/server.test.cjs

실제 임시 SQLite 파일과 HTTP API로 가입·로그인, 작성자 권한, 평가 중복 방지, 별점/댓글 독립 삭제, 계정별 북마크 집계, 백업 재가져오기, 서버 재시작 후 사진·평가·세션 지속성을 검사합니다. 테스트 데이터는 실제 앱 DB와 분리됩니다.
